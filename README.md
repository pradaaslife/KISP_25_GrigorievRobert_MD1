# Конспект с Expo

## Структура и организация процессов
**Этапы жизненного цикла:** Вся документация разделена по шагам работы над приложением. Раздел **Develop** содержит инструменты для написания кода и навигации, **Review** отвечает за совместное тестирование, **Deploy** описывает публикацию в магазины, а **Monitor** отслеживает работу сервисов в продакшене.

**Формат для ИИ-агентов:** Текст страниц адаптирован для чтения языковыми моделями (LLM). Если добавить расширение *.md* к любому URL-адресу документации, она откроется в виде чистого Markdown-файла.

## Возможности платформы и SDK
**Универсальный код:** Разработчик пишет один проект на JavaScript/TypeScript, который работает на Android, iOS и в веб-браузерах.

**Файловый роутинг:** Модуль **Expo Router** строит навигацию между экранами приложения автоматически на основе структуры папок и файлов проекта.

**Компоненты SDK:** Платформа предоставляет встроенные модули для доступа к функциям устройств. В качестве примеров в документации выделены модули Image (изображения), **Camera** (камера) и **Notifications** (уведомления).

**Тестирование без установки:** Инструмент **Expo Snack** позволяет запускать и проверять код приложения прямо в браузере без настройки локального окружения.

## Интеграция с искусственным интеллектом (AI)
**Инструменты для агентов:** В документацию добавлен отдельный блок по работе с ИИ. Он содержит руководства по **Expo Skills**, **MCP Server**, готовые наборы инструментов (**Agent toolkits**) и разделы для интеграции с **LLM.**

**Примеры реализации:** На сайте представлены готовые проекты для изучения, среди которых есть пример интеграции **API Routes + Open AI.**

## Консольные команды и автоматизация (CLI)
*npx create-expo-app@latest* — Команда для создания и инициализации нового чистого проекта.

*npx testflight* — Эксклюзивная команда для iOS, которая загружает готовую сборку приложения на платформу TestFlight.

*npx eas-cli deploy* — Инструмент для развертывания и публикации веб-версии вашего приложения.

**Сервис EAS Workflows:** Используется для настройки автоматического CI/CD цикла, позволяя собирать и выпускать релизы напрямую через GitHub.


# Конспект Epro tutorial

## 1. Introduction (Введение)

**Expo** — это экосистема поверх React Native, упрощающая создание, сборку и развертывание кроссплатформенных приложений (Android, iOS, Web) из единой кодовой базы.

**Expo Go** — мобильное приложение-песочница для мгновенного тестирования кода на реальном устройстве через QR-код без локальной настройки Android Studio/Xcode.

## 2. Create your first app (Создание первого приложения)

**Инициализация:** Проект создается командой *npx create-expo-app@latest*.

**Запуск сервера:** Команда *npx expo start* поднимает Metro Bundler и выводит QR-код в терминал.

**Архитектура:** По умолчанию современный шаблон создает структуру папки *src/app* для файлового роутинга.

## 3. Add navigation (Добавление навигации)

**Expo Router:** Файловая система определяет экраны (файл *index.tsx* равен пути */*).

**Stack Navigator:** Организует навигацию по принципу стопки карт (*Stack*). Каждый новый экран открывается поверх предыдущего свайпом или анимацией.

**Tab Navigator:** Реализует нижнюю панель вкладок. Для группировки папка оборачивается в круглые скобки (*tabs*), чтобы исключить её название из адресной строки URL.

**Компонент** *Link*: Используется для перехода: *Link href="/about">Перейти</Link*.

**404:** Файл *+not-found.tsx* перехватывает любые несуществующие маршруты.

## 4. Build a screen (Создание экрана)

**Базовые UI-компоненты:**
*View* — контейнер-блок (аналог *div* в веб-разработке).
*Text* — текстовый компонент (любая строка обязана быть внутри него).
*Pressable* или *TouchableOpacity* — компоненты-обертки для обработки нажатий.

**Стилизация:** Используется встроенный *StyleSheet.create()*. Стили основаны на модели **Flexbox**, где направление по умолчанию выставлено как *flexDirection:* *'column'* (вертикально).

## 5. Use an image picker (Использование Image Picker)

**Библиотека:** *expo-image-picker*.

**Доступ к галерее:** Требует асинхронного запроса разрешений у операционной системы: *typescriptconst [status, requestPermission] = ImagePicker.useMediaLibraryPermissions();*

**Выбор фото:** Метод *launchImageLibraryAsync()* открывает системную галерею и возвращает объект с URI выбранного изображения для последующего отображения в компоненте *Image*.

## 6. Create a modal (Создание модального окна)

**Компонент *Modal*:** Стандартный компонент React Native для всплывающих окон поверх основного интерфейса.

**Управление:** Состояние видимости контролируется через логический стейт (например, *const [isVisible, setIsVisible] = useState(false))*.

**Свойства:** Атрибут *animationType="slide"* задает анимацию появления снизу, а *transparent={true}* позволяет делать полупрозрачный размытый или затемненный фон.

## 7. Add gestures (Добавление жестов)

**Инструментарий:** *react-native-gesture-handler* и *react-native-reanimated*.

**Связка компонентов:** Для работы жестов все приложение необходимо обернуть в *GestureHandlerRootView*.

**Реализация:** Компоненты вроде *PanGestureHandler* (для перетаскивания) или *TapGestureHandler* (для тапов) отслеживают координаты пальца, а Reanimated плавно обновляет положение объекта в обход основного потока JavaScript.

## 8. Take a screenshot (Создание скриншота)

**Библиотека:** *react-native-view-shot*.

**Принцип действия:** Компонент захватывает переданную область интерфейса (через *ref*) и конвертирует её в локальную ссылку-изображение (URI).

**Сохранение в галерею:** Полученный URI передается в модуль *expo-media-library* с помощью функции *MediaLibrary.saveToLibraryAsync(localUri)*.

## 9. Handle platform differences (Обработка межплатформенных различий)

**Модуль** *Platform:* Позволяет писать разветвления в коде в зависимости от ОС: *typescriptconst padding = Platform.OS === 'ios' ? 20 : 10;*

**Расширения файлов:** Metro автоматически выберет нужный файл, если дать ему специфичное расширение: *Button.ios.tsx*, *Button.android.tsx* или *Button.web.tsx.*

## 10. Configure status bar, splash screen and app icon (Настройка системных элементов)

**Status Bar:** Компонент *StatusBar style="light" /* управляет цветом системных иконок (время, батарея) в верхней части экрана.

**Конфигурация** (*app.json*): Глобальный файл настроек проекта, где задаются:
*icon* — квадратная иконка приложения (1024x1024px).
*splash* — параметры экрана загрузки (фоновый цвет и логотип).
*adaptiveIcon* — специфические настройки адаптивных иконок для Android.

## 11. Learning resources (Ресурсы для обучения)

**Дальнейшие шаги:**
Изучение **EAS (Expo Application Services)** для облачной сборки бинарников (*.apk*, *.aab*, *.ipa*) без наличия macOS.
Работа с нативными модулями через конфигурационные плагины (Config Plugins).
Интеграция с базами данных (SQLite, Firebase, Supabase).

# Конспект JavaScript

## 1. Введение в JavaScript

### Что такое JavaScript
- JavaScript изначально придумали, чтобы «оживлять» веб-страницы.
- Программы на JS называют **скриптами**. Они встраиваются прямо в HTML и запускаются автоматически при загрузке страницы, без компиляции — исполняются как обычный текст.
- Несмотря на схожее название, JavaScript и Java — разные языки. Изначально JS назывался «LiveScript», но его переименовали, чтобы использовать популярность Java в маркетинговых целях.
- Со временем JS стал самостоятельным языком со своей спецификацией — **ECMAScript**.
- JS может выполняться не только в браузере, но и на сервере (Node.js) и других устройствах — везде, где есть специальная программа-«движок» (например, V8 в Chrome, SpiderMonkey в Firefox).

### Что может JS в браузере
- Добавлять и изменять HTML/CSS «на лету».
- Реагировать на действия пользователя (клики, движения мыши, нажатия клавиш).
- Отправлять запросы на сервер, загружать и скачивать файлы (AJAX).
- Работать с cookie, показывать всплывающие окна, сохранять данные локально (localStorage).

### Чего JS не может в браузере (ради безопасности)
- Не может свободно читать/писать файлы на диске или запускать программы — доступ к файлам возможен только через явные действия пользователя (drag-n-drop, `<input>`).
- Не может получить доступ к содержимому другой вкладки/окна, если они с другого домена — это ограничение называется **Same Origin Policy**.
- Ограничен в отправке запросов на другие сайты/домены без явного согласия удалённой стороны.

### Что делает JS особенным
Три сильные стороны, которые редко встречаются вместе у одного языка:
1. Полная интеграция с HTML/CSS.
2. Простые вещи делаются просто.
3. Поддержка всеми основными браузерами «из коробки».

### Языки поверх JavaScript
Так как синтаксис JS подходит не для всех задач, появились языки, которые транспилируются (конвертируются) в JS перед запуском в браузере:
- **CoffeeScript** — более короткий и лаконичный синтаксис.
- **TypeScript** — добавляет строгую типизацию (разработка Microsoft).
- **Flow** — тоже добавляет типизацию (разработка Facebook).
- **Dart** — отдельный язык от Google со своим движком.
- **Brython** — транспилирует Python в JS.

- **caniuse.com** — поддержка конкретных возможностей разными браузерами.

## 3. Редакторы кода

Два основных типа редакторов — многие разработчики используют по одному из каждого типа.

### IDE (интегрированная среда разработки)
Мощные редакторы, работающие на уровне всего проекта: переключение между файлами, автодополнение по всему проекту, интеграция с git и инструментами тестирования.
- **Visual Studio Code** — кроссплатформенный, бесплатный.
- **WebStorm** — кроссплатформенный, бесплатный для некоммерческого использования.
- **Visual Studio** (не путать с VS Code) — платная, только для Windows, хороша для .NET.

### «Лёгкие» редакторы
Менее мощные, но быстрые и простые — удобны, чтобы быстро открыть и отредактировать один файл.
- **Sublime Text** — кроссплатформенный, условно-бесплатный.
- **Notepad++** — только Windows, бесплатный.
- **Vim** и **Emacs** — мощные, но требуют навыка работы с ними.

Выбор редактора — дело индивидуальное, зависит от привычек и задач.

## 4. Консоль разработчика

- По умолчанию браузер не показывает ошибки в коде явно — для этого существуют **инструменты разработчика (DevTools)**.
- Открываются клавишей `F12` (на Mac для Chrome — `Cmd+Opt+J`).
- Во вкладке **Console**:
  - видны ошибки скрипта (обычно красным цветом) со ссылкой на строку кода, где произошла ошибка;
  - есть командная строка (символ `>`), где можно вводить и выполнять JS-код по нажатию `Enter`;
  - `Shift+Enter` — перенос строки для многострочного ввода.
- В Safari (только Mac) сначала нужно включить пункт меню «Разработка» в настройках браузера, затем консоль открывается через `Cmd+Opt+C`.
- В Firefox, Edge и большинстве других браузеров DevTools открываются также по `F12` и работают похожим образом.

## 5. Основы JavaScript

### 5.1 Привет, мир!

- JS-код вставляется в HTML с помощью тега `<script>`:

```html
<script>
  alert('Привет, мир!');
</script>
```

- Атрибуты `type` и `language` у тега `<script>` сегодня не нужны — это пережитки старого HTML.
- Внешний скрипт подключается через атрибут `src`:

```html
<script src="/path/to/script.js"></script>
```

- Плюс вынесения кода в отдельный файл — браузер кэширует его, и при повторных обращениях файл не скачивается заново.
- **Важно:** если у тега `<script>` указан `src`, содержимое внутри тега игнорируется — нельзя одновременно подключать внешний файл и писать код внутри того же тега.

### 5.2 Структура кода

**Инструкции** — это синтаксические конструкции, выполняющие действие (например, `alert('Привет')`). Обычно каждую инструкцию пишут на отдельной строке для читаемости.

**Точка с запятой**
- В большинстве случаев её можно не ставить — перенос строки чаще всего трактуется как автоматическая точка с запятой (ASI).
- Но бывают исключения, когда автоматическая расстановка «не срабатывает» и код может привести к ошибке (например, если следующая строка начинается с квадратной скобки `[`).
- Рекомендация: ставить точку с запятой всегда, даже когда без неё код работает — это общепринятая практика.

**Комментарии**
- Однострочный: `// текст комментария`.
- Многострочный: `/* текст */`.
- Вложенные многострочные комментарии не поддерживаются.
- Комментарии не влияют на выполнение и не увеличивают итоговый размер продакшн-кода — их вырезают минификаторы.

### 5.3 Строгий режим — "use strict"

- До ES5 (2009 год) язык менялся с сохранением полной обратной совместимости — из-за этого некоторые старые ошибки навсегда «застряли» в языке.
- ES5 добавил улучшения, которые по умолчанию отключены (чтобы не сломать старый код) и включаются явной директивой:

```javascript
"use strict";
```

- Директива должна находиться **в самом начале** скрипта или функции — выше могут быть только комментарии, иначе строгий режим не включится.
- Отменить `use strict` после включения нельзя.
- В консоли браузера строгий режим по умолчанию выключен — чтобы включить его там, нужно ввести `'use strict';`, затем `Shift+Enter` и уже дальше — свой код.
- Современные конструкции — **классы** и **модули** — включают строгий режим автоматически, поэтому директива для них не нужна.
- Рекомендация: пока код не состоит целиком из классов/модулей, стоит начинать скрипты с `"use strict"`.

### 5.4 Переменные

- Переменная — «именованное хранилище» для данных. Объявляется ключевым словом `let`:

```javascript
let message;
message = 'Hello';
// или сразу:
let message = 'Hello';
```

- Несколько переменных лучше объявлять на отдельных строках — так код читабельнее (хотя через запятую тоже работает).
- `var` — устаревший аналог `let` из старого кода, между ними есть тонкие различия.
- Значение переменной можно менять сколько угодно раз; при присвоении нового значения старое стирается.
- Повторное объявление переменной через `let` в той же области видимости — ошибка (`SyntaxError`).

**Имена переменных**
- Разрешены буквы, цифры, `$` и `_`; первый символ не может быть цифрой.
- Обычно используется camelCase (`myVeryLongName`).
- Регистр важен: `apple` и `APPLE` — разные переменные.
- Нельзя использовать зарезервированные слова (`let`, `class`, `return`, `function` и т.д.) в качестве имени.
- Без `use strict` можно создать переменную простым присваиванием без `let` — это устаревшая практика, в строгом режиме она вызывает ошибку.

**Константы**
- Объявляются через `const` — значение после присвоения изменить нельзя.
- Константы с «жёстко закодированным» значением, известным заранее, принято называть заглавными буквами с подчёркиванием (`COLOR_RED`); константы, которые вычисляются во время выполнения, пишут обычным регистром.

**Хорошие имена переменных**
- Имя должно ясно отражать содержимое (`userName`, `shoppingCart`), а не быть абстрактным (`data`, `value`).
- Не стоит экономить на количестве переменных ради «удобства» — дополнительная переменная помогает и читаемости, и отладке, а не вредит производительности.

### 5.5 Типы данных

Значение в JS всегда имеет определённый тип, но переменная не привязана к типу — язык **динамически типизированный**. Всего 8 основных типов:

1. **number** — числа, включая дробные, а также специальные значения `Infinity`, `-Infinity` и `NaN` (результат некорректной математической операции). Математические операции в JS «безопасны» — скрипт не «падает», в худшем случае возвращает `NaN`.
2. **bigint** — для целых чисел произвольной длины, выходящих за пределы безопасного диапазона `number` (`±(2^53-1)`). Создаётся добавлением `n` в конце: `1234567890123456789012345678901234567890n`.
3. **string** — строки. Три вида кавычек: двойные и одинарные — равнозначны, обратные (бэктики) — позволяют вставлять выражения через `${...}` (шаблонные строки):

```javascript
let name = "Иван";
alert(`Привет, ${name}!`); // Привет, Иван!
```

4. **boolean** — только `true` и `false`, часто результат сравнений.
5. **null** — специальное значение «пусто» / «неизвестно», отдельный тип.
6. **undefined** — означает «значение не присвоено»; такое значение получает объявленная, но не инициализированная переменная.
7. **object** — единственный не примитивный тип, хранит сложные структуры и коллекции данных.
8. **symbol** — используется для уникальных идентификаторов объектов.

**Оператор `typeof`**
- Возвращает строку с именем типа: `typeof 5` → `"number"`, `typeof "foo"` → `"string"` и т.д.
- Особенности: `typeof null` возвращает `"object"` — это историческая ошибка языка; `typeof alert` (функция) возвращает `"function"`, хотя отдельного типа «функция» в JS нет — функции технически относятся к объектам.

### 5.6 Взаимодействие: alert, prompt, confirm

Три встроенные функции браузера для простого общения с пользователем — все три **модальные** (блокируют работу со страницей, пока окно не закрыто), и их внешний вид задаётся браузером, а не разработчиком.

- **`alert(message)`** — показывает сообщение и ждёт нажатия «ОК».
- **`prompt(title, [default])`** — показывает окно с текстом и полем ввода:
  - `title` — текст сообщения;
  - `default` (необязательный) — значение по умолчанию в поле ввода.
  - Возвращает введённый текст, либо `null`, если пользователь нажал «Отмена» или `Esc`.

```javascript
let age = prompt('Сколько тебе лет?', 100);
alert(`Тебе ${age} лет!`);
```

- **`confirm(question)`** — окно с вопросом и кнопками «ОК»/«Отмена». Возвращает `true` при нажатии «ОК», иначе `false`.

```javascript
let isBoss = confirm("Ты здесь главный?");
alert(isBoss); // true или false
```
